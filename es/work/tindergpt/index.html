Resumen

TinderGPT empezó como una pregunta en broma —¿podría un LLM mantener viva una conversación en una app de citas?— y se convirtió en un proyecto open source con 22 estrellas y en el tema de mi charla en NodeBR #63 en São Paulo.

El problema

Iniciar y mantener conversaciones es repetitivo. La pregunta técnica era cómo construirlo para poder cambiar el proveedor de IA y la plataforma sin reescribir la app.

Qué hice

Una API en Express con TypeScript usa patrones factory tanto para los proveedores de IA como para las plataformas sociales, un contenedor de dependencias y middleware de autenticación, con Redis para guardar la autenticación. Un panel en React (Ant Design) controla filtros de segmentación como la distancia y la bio. Todo corre con Docker Compose.

Arquitectura

La API enruta cada acción a través de dos factories —una para plataformas sociales y otra para proveedores de IA—, de modo que las nuevas integraciones solo suman.

  • React dashboard
  • Express API
  • Social-platform factory
  • AI-provider factory
  • Redis (auth)
  • Tinder API
  • OpenAI

Retos de ingeniería

  1. Respetar los límites de peticiones de la plataforma (HTTP 429) con un ritmo deliberado.
  2. Diseñar prompts que produzcan mensajes naturales y adaptados al contexto.

Resultados

  • 22 estrellas en GitHub: mi repositorio con más estrellas.
  • Presentado en NodeBR #63 (São Paulo, 2023).

Aprendizajes

  • Las abstracciones sobre los proveedores de LLM se amortizan de inmediato: el panorama de modelos cambia cada mes.
