Visão geral

O RickOS é a ferramenta que uso para organizar meus dias. Começou como um simples controle de horas trabalhadas e cresceu, um módulo de cada vez, até virar um painel único: controle de tempo em linha do tempo com Pomodoro, inbox/TODO/hábitos, um Learning OS (roadmaps, anotações em Markdown, flashcards gerados por IA com repetição espaçada SM-2, quizzes e exportação para o Obsidian), finanças, um monitor de preços de passagens, projetos sincronizados com o GitHub e um verificador da saúde das worktrees.

O problema

Meu trabalho, meus estudos e meu planejamento pessoal viviam em uma dúzia de apps que não conversavam entre si, e nenhum deles conseguia usar as ferramentas de IA que eu já uso todos os dias.

O que eu fiz

Um servidor Fastify headless é o único dono do banco e expõe tudo por um único endpoint RPC mais server-sent events. O app Electron e uma PWA que uso no celular são apenas clientes desse servidor. As funcionalidades de IA chamam a CLI local do Claude Code, transmitem os resultados ao vivo e podem rodar em segundo plano.

Arquitetura

Os dois clientes conversam com um único servidor Fastify via RPC + SSE. O SQLite roda em WebAssembly (sql.js) com migrações versionadas; os segredos são criptografados com AES-256-GCM; o acesso remoto exige um token.

  • Electron desktop
  • PWA on phone
  • Fastify · RPC + SSE
  • SQLite (sql.js / WASM)
  • Claude Code CLI
  • GitHub · Calendar · Finance

Camada de IA

  • Prompt Runner: abas paralelas que combinam um agente, um conjunto de skills, um projeto e um prompt, executados pela CLI local do Claude Code com streaming ao vivo.
  • Brain dump: texto livre entra, tarefas, projetos e eventos de agenda saem.
  • Flashcards e quizzes gerados por IA no Learning OS, e um briefing diário no dashboard.
  • O uso de tokens de cada execução de IA é registrado por módulo e por projeto.

Módulos

  • Controle de tempo: linha do tempo contínua de 24 horas com blocos arrastáveis, tags, Pomodoro, heatmap mensal e banco de horas.
  • Organização: inbox com atalho global de captura, TODO com prioridades e prazos, hábitos com grade mensal e insights, revisão semanal e base de conhecimento.
  • Projetos: issues do GitHub em Kanban e um verificador que aponta branches e worktrees locais em risco, esquecidas, órfãs ou prontas para limpar.
  • Finanças, viagens (monitor de preços de passagens) e links, todos opcionais e configuráveis.

Engenharia

  • Um único registro de RPC compartilhado entre desktop e web: os mesmos handlers atendem o Electron e o celular.
  • Um script com Playwright captura todas as páginas em tamanho desktop e celular, nas duas skins visuais, para revisar mudanças de interface lado a lado.
  • Snapshots diários do banco e exportação e importação em um único arquivo.

Desafios de engenharia

  1. Manter uma única fonte de verdade atendendo um app desktop e um celular ao mesmo tempo.
  2. Rodar jobs longos de IA (prompt runner, brain dump → tarefas, geração de flashcards) sem travar a interface.
  3. Integrar GitHub, OAuth multi-conta do Google Calendar, Pluggy Open Finance e Skyscanner atrás de uma interface consistente.

Resultados

  • Ferramenta de uso diário com mais de 170 commits, e contando.
  • Roda como app desktop e como PWA instalável, a partir do mesmo servidor e do mesmo banco.
  • Suíte automatizada de screenshots com Playwright que captura todas as páginas em tamanho desktop e celular, em duas skins.

Aprendizados

  • Local-first com um servidor enxuto é uma arquitetura surpreendentemente poderosa para software pessoal.
  • Tratar uma CLI de IA como um subprocesso que você orquestra é mais flexível do que embutir uma única chamada de API.
