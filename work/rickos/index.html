Overview

RickOS is the tool I use to run my own days. It began as a simple working-time tracker and grew, one module at a time, into a single panel: a timeline time tracker with Pomodoro, inbox/TODO/habits, a Learning OS (roadmaps, Markdown notes, AI-generated flashcards with SM-2 spaced repetition, quizzes and Obsidian export), finances, a flight-price monitor, GitHub-synced projects and a worktree health scanner.

The problem

My work, study and personal planning lived in a dozen apps that didn't talk to each other, and none of them could use the AI tooling I already rely on every day.

What I did

A headless Fastify server is the only owner of the database and exposes everything through a single RPC endpoint plus server-sent events. The Electron app and a PWA I use on my phone are just clients of that server. AI features shell out to the local Claude Code CLI, stream results live and can run in the background.

Architecture

Both clients talk to one Fastify server over RPC + SSE. SQLite runs in WebAssembly (sql.js) with versioned migrations; secrets are encrypted with AES-256-GCM; remote access requires a token.

AI layer

  • Prompt Runner: parallel tabs that combine an agent, a set of skills, a project and a prompt, run through the local Claude Code CLI with live streaming.
  • Brain dump: free text in, tasks, projects and calendar entries out.
  • AI-generated flashcards and quizzes in the Learning OS, and a daily briefing on the dashboard.
  • Token usage of every AI run is recorded per module and per project.

Modules

  • Time tracker: a continuous 24-hour timeline with draggable blocks, tags, Pomodoro, a monthly heatmap and an hour bank.
  • Organisation: inbox with a global capture shortcut, TODO with priorities and due dates, habits with monthly grids and insights, weekly review and a knowledge base.
  • Projects: GitHub issues on a Kanban board, and a scanner that flags local branches and worktrees that are at risk, forgotten, orphaned or safe to clean.
  • Finances, travel (flight-price monitoring) and links, all optional and configurable.

Engineering

  • One RPC registry shared by the desktop and the web: the same handlers serve Electron and the phone.
  • A Playwright script captures every page at desktop and phone sizes in two visual skins, so UI changes are reviewed side by side.
  • Daily database snapshots and a one-file export and import.

Engineering challenges

  1. Keeping one source of truth while serving a desktop app and a phone at the same time.
  2. Running long AI jobs (prompt runner, brain dump → tasks, flashcard generation) without blocking the UI.
  3. Integrating GitHub, multi-account Google Calendar OAuth, Pluggy Open Finance and Skyscanner behind one consistent interface.

Outcomes

  • Daily-driver tool with 170+ commits and counting.
  • Runs as a desktop app and as an installable PWA from the same server and database.
  • Automated Playwright screenshot suite that captures every page at desktop and phone sizes in two skins.

Lessons

  • Local-first plus a thin server is a surprisingly powerful architecture for personal software.
  • Treating an AI CLI as a subprocess you orchestrate is more flexible than embedding a single API call.
