Overview

TinderGPT started as a playful question — could an LLM keep a dating-app conversation going? — and became an open-source project with 22 stars and the subject of my talk at NodeBR #63 in São Paulo.

The problem

Starting and sustaining conversations is repetitive. The technical question was how to build it so the AI provider and the platform could be swapped without rewriting the app.

What I did

A TypeScript Express API uses factory patterns for both AI providers and social platforms, a dependency container and auth middleware, with Redis for auth storage. A React (Ant Design) dashboard controls targeting filters such as distance and bio. Everything runs with Docker Compose.

Architecture

The API routes every action through two factories — one for social platforms, one for AI providers — so new integrations are additive.

  • React dashboard
  • Express API
  • Social-platform factory
  • AI-provider factory
  • Redis (auth)
  • Tinder API
  • OpenAI

Engineering challenges

  1. Respecting the platform's rate limits (HTTP 429) with deliberate pacing.
  2. Designing prompts that produce natural, context-aware messages.

Outcomes

  • 22 GitHub stars — my most-starred repository.
  • Presented at NodeBR #63 (São Paulo, 2023).

Lessons

  • Abstractions around LLM providers pay off immediately — the model landscape changes monthly.
